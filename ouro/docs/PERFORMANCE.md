# Ouro を「サクサク」動かすための30の仕組み

すべて**外部ランタイム依存なし**（仮想化ライブラリ等を入れない方針）で実装している。
数字は Playwright + Chromium、CPU 4倍スロットル、同一手順で実装前後を計測したもの。

| | 実装前 | 実装後 |
|---|---|---|
| 起動〜表紙が出るまで | 1642ms | **554ms** |
| 最初に読み込む量 | 499KB | **105KB** |
| 画像の合計 | 2.2MB | **176KB** |
| 6〜7文字入力したときの保存 | 5回・138KB | **1回・1KB** |
| いちばん長い処理の時間 | 784ms | **358ms** |

アプリ内の計測（項目30／会社画面「速さの記録」）では、画面の切り替えが中央値54ms・
最悪84ms、保存が中央値7ms。

---

## A. 起動を軽くする（1〜7）

1. **画面ごとの遅延読み込み** — 下部ナビの6画面と常設バー以外は `lazy()`＋`<Suspense>`
   （`src/App.jsx`）。新しい画面も原則 lazy にする。
2. **束の分割** — `vite.config.js` の `manualChunks` で `react` と `roster`
   （`characters.js`＋`roles.js`＝30名分の人物データ）を本体から切り離す。
   人物データは名鑑を開くまで読み込まれない。
3. **表紙のSVG化** — 393KBのJPEGだった紋章を `components/Seal.jsx` でその場で描く
   （画像ファイルを持たない）。読み込み待ちが無くなり、拡大しても滲まない。
4. **写真の圧縮** — チーム写真 1809KB(PNG) → 136KB(JPEG・幅1200px)、
   favicon 393KB → 38KB。`ouro-seal.jpg` は3.のSVGに置き換えて削除。
5. **二段階の起動** — `useStore.js` は最初の描画に要る10キー（`FIRST_KEYS`）だけ先に読み、
   残り（`REST_KEYS`＝部署・出典・会議・操作履歴・接続）は描画後に読む。
6. **初回だけメモリ上で組み立てる** — 初回起動の初期データは保存→読み直しをせず、
   組み立てた結果をそのまま画面へ出し、保存は後ろで走らせる。
7. **Service Worker** — `public/sw.js`。HTMLは network-first（コードは常に最新）、
   `/assets/` のハッシュ付きファイルと画像・フォントは cache-first。
   2回目以降の起動が体感で変わる。
   ※ **古いキャッシュを消すときは名前の頭で絞る**。同じドメイン（GitHub Pages）に
   同梱された他のアプリと CacheStorage を共有しているので、名前を見ずに消すと
   そちらのキャッシュまで巻き添えで消える（Ouroは `ouro-`、鍼灸アプリは `shinkyu-`）。

## B. 保存を軽くする（8〜14）

8. **書き込みの先送り（デバウンス）** — `storage.js` が同じキーへの連続保存をまとめる。
9. **同じ中身なら書かない（重複排除）** — 直前と同じJSONなら書き込みを捨てる。
10. **暇な時に書く** — `requestIdleCallback` があれば手が空いた時に流す。
11. **離れる直前に必ず書く** — `pagehide` / `beforeunload` / `visibilitychange`(hidden)
    で強制的に書き出す。先送りしても消えない。
12. **1件ずつ保存する** — `RECORD_COLLECTIONS`（社員・知識・出典・仕事・会議・案件・承認・
    操作履歴）は配列まるごとではなく**変わった1件だけ**を書く。
    社員1人の編集で18人分を書き直さない。
13. **目録（manifest）で順序を持つ** — `ids` 方式は並び順のIDリストを、
    `sorted` 方式（操作履歴）は時刻順のキーを使い、読み出しは
    `idbGetMany` / `idbGetPrefix` の1トランザクションで済ませる。
14. **書き出し前に必ず流し切る** — `flushNow()` は実行中の書き込みも待つ
    （待たないと、書き出したデータに最後の操作が入らない）。

## C. 画面の描画を軽くする（15〜21）

15. **見えていない所を描かない** — 長い一覧の行に `content-visibility: auto`
    （`styles.css`）。※ `::before` で線や点を描いている要素（`.step`）には**付けない**
    （はみ出す装飾が切り落とされるため。実際に一度やって消えた）。
16. **`React.memo`** — `Row` / `Portrait` など、同じ引数なら描き直さない。
17. **肖像の共有部品化** — 額縁と切り抜きの定義を `PortraitSprite` に1つだけ置き、
    各肖像は `<use href="#ouro-portrait-frame" />` で参照する。
    30名並べても定義は1つ（テストが機械チェック）。
18. **小さい肖像は簡略に描く** — 一覧では `compact` / `small` で線を減らす。
19. **入力の遅延反映** — 目次の検索は `useDeferredValue`。打っている間に一覧の
    作り直しが追いつかなくなるのを防ぐ。
20. **段階表示** — 目次は先頭120件だけ描き、「もっと見る」で伸ばす。
    ただし**五十音バーは絞り込み結果の全体から作る**（120件の外の行にも飛べる。
    飛ぶ時は先に枠を伸ばしてからスクロールする）。
21. **カレンダーの索引化** — `schedule.js` の `buildDayIndex()` が
    「日付→その日の予定」の Map を1回だけ作る。マス目ごとに全件を走査しない。

## D. AIの待ち時間を短くする（22〜26）

22. **流し受け（ストリーミング）** — `lib/providers/stream.js` の `readSse()` を
    Claude / GPT / Gemini の3つで共用。書き上がるのを待たず、途中から画面に出る。
23. **描き直しの間引き** — `throttleDelta()` が90msごとにまとめて反映する
    （1文字ごとに描き直すと、かえって遅くなる）。
24. **意見・反論を同時に走らせる** — AI会議の意見出しと反論は `Promise.all`。
    5人なら5倍待つ、をやめる。
25. **仕事の途中経過を出す** — `runStep` の `onDelta` で、いま書いている文章が
    そのまま仕事の画面に流れる。
26. **中断からの復帰** — 起動時に「実行中」のまま残っている仕事を「待機」へ戻す
    （閉じた瞬間の仕事が永遠に回り続けない）。

## E. 体感と計測（27〜30）

27. **押した瞬間に反応する** — 承認ボタンは先に仕事の画面へ移ってから処理する。
    「押したのに何も起きない」時間を作らない。
28. **待ちの見た目を統一する** — `<Suspense>` の待ち表示を画面と同じ黒地にして、
    白い板が一瞬光るのを無くす。
29. **アニメーションを控えめに** — `prefers-reduced-motion` を尊重し、
    影・ぼかしを避けて合成を軽くする。
30. **アプリ内の速さの記録** — `lib/perf.js`。画面の切り替え・保存・AI実行の
    所要時間を**端末の中だけ**に記録し、会社画面の「速さの記録」で中央値と最悪値を見る。
    どこが遅いかを推測でなく数字で決めるため。ネットワークには一切送らない。

# 第2弾：さらに30項目（2026-08-25）

上の30項目のあとに入れたもの。**上と重ならないものだけ**を選んである
（「暇な時に次の画面を取っておく」は第1弾で入っていたので、第2弾では
対象を広げ、通信の細い端末では見送る、という形に変えた）。

| | 第1弾のあと | 第2弾のあと |
|---|---|---|
| 起動〜表紙が出るまで | 554ms | **395ms** |
| 最初に読む量（gzip） | 45.1KB | **43.2KB**（本体のみ。React込みの合計は103.9KB） |
| 画面の切り替え（中央値） | 54ms | **27ms** |

計測は `npm run perf`（CPU4倍スロットル）。基準は `scripts/perf-baseline.json`。

## F. 起動をさらに削る（1〜6）

1. **押す前に読み込む** — `lib/preload.js`。lazy() と先読みが同じ読み込み関数を指す。
   下部ナビ・会社画面の行は、指が触れた時点（pointerdown/enter）で読み始める。
2. **先読みの対象を広げ、細い通信では見送る** — 会社バーから開く4画面も対象に。
   節約モード・2G相当のときは先読みしない（本命の通信の邪魔になるため）。
3. **名鑑データを索引と本文に割る** — `data/characters.js` は名前・読み・持ち味・
   肖像だけ。出身・人物像・書き方は `data/characterDetails.js` にあり、
   名鑑を開く／雇う時に初めて読む。**読み込み前は席の持ち味で代用する**ので、
   空の人物像で雇われることはない。
4. **初回だけ要るものを初回だけ読む** — 席を数えるだけの `lib/seats.js` と
   設定の初期値の `lib/defaults.js` を切り出し、`seed.js` と `data/employees.js` を
   動的読み込みへ。社員一覧・目次が「席を数える」ためだけに初期データ一式を
   読む状態を解消した。この変更で雇用系の関数は非同期になっている。
5. **1枚目をHTMLに埋め込む** — 黒地と待ちの輪を `index.html` に直接書く。
   **ここに増やさないこと**（増やすほど最初の1枚が遅くなる）。
6. **起動直後の読み出しを描画とぶつけない** — `lib/idle.js`（afterPaint / whenIdle）。

## G. 保存と読み出し（7〜12）

7. **書き込みの優先度** — `save(key, value, 'low')` は2.5秒待ってまとめる（操作履歴）。
   編集中のものは従来どおり0.4秒。**閉じる直前の書き切りは期限を無視して全部書く**。
8. **古い記録を畳む** — `audit.js` の `foldAudit()`。30日より古い記録を日ごとに1件へ。
   **消さずに畳む**ので件数と費用は残る。**1日に1度だけ**走る
   （毎起動で走らせると、9のページングが数秒で無効になる）。
9. **操作履歴のページング** — 起動時は新しい400件だけ（`db.js` の `idbGetPrefixLast`）。
   一部だけ読んだコレクションには印を付け、**読んでいない古いレコードを
   「消された」と誤解して削除しない**。書き出し（exportAll）は track:false で読む。
10. **保存容量の見張り** — `storageEstimate()`。9割を超えたら会社画面で知らせる。
11. **JSON化を1キーにつき1回** — 判定と書き込みで2回まわしていたのをやめた。
12. **タブ間の同期** — `BroadcastChannel` で**キーの名前だけ**流し、受け取った側が
    読み直す。中身は流さない（保存の窓口を1つに保つため）。

## H. 描画（13〜19）

13. **`useTransition`** — 目次の絞り込み・切替、名鑑の役職を開く／チーム切替。
14. **見えている範囲だけ描く** — `components/Window.jsx`（自前・外部ライブラリなし）。
    **行の高さがそろっていることが前提**なので、使う時は行を固定高にする。
    高さの数値は JSX と CSS の2か所にあるので、必ず両方そろえる。
15. **絞り込み結果を1組だけ覚える** — 目次は画面を離れると捨てられるので useMemo は
    効かない。`data/toc.js` の `buildToc` / `filterToc` に1件キャッシュ。
16. **並び順を key にしない** — 依頼の手順と提案が index を key にしていた。
17. **形の変わらない図は描き直さない** — Spark（折れ線）と OrgMap を memo 化。
    ※ 行頭の記号（▤ ◈ ⚒）は文字なので `<symbol>` の共有は当てはまらない。
18. **長い成果物を折り畳む** — `Doc` は24段落を超えたら先頭だけ。
    **流れてくる途中の文字には効かせない**（書いているのに止まって見える）。
19. **合成レイヤーの決まり** — `will-change` は常に画面にある3つだけ。

## I. AIの待ち時間（20〜25）

20. **中断できる** — `AbortController` を実行ごとに持ち、仕事の画面に「やめる」。
    止めればそこから先の利用料はかからない。
21. **同じ問いの答えを使い回す** — 端末のメモリだけ・20件。道具（Web検索）を使う
    手順は対象外。使い回した時は費用を二重に数えない。
22. **手順を同時に走らせる** — 仕事の流れの steps に入れ子を書く：
    `['researcher', ['analyzer','reviewer'], 'strategist']`。
    **同時の手順は全部そろってから次へ引き継ぐ。**
    引き継ぎ先は「g+1」ではなく**残っている番号の中の次**を探すこと
    （未雇用の役職を外すと番号が飛ぶ）。承認は必ず単独で最後。
23. **渡す材料を切り詰める** — `memory.js` の `trimTail`。**末尾を残して古い方を削る**。
24. **混んでいる時だけ1度やり直す** — 429/503/529 のみ。キー違いは繰り返さない。
25. **詰まっているエンジンを避ける** — 60秒だけ。他に無ければ避けない。

## J. 体感と、遅くならない仕組み（26〜30）

26. **押した瞬間の手応え** — `ui.jsx` の `Action`。二度押しの防止も兼ねる。
27. **骨組み表示** — 読み込み中は輪ではなく、次に出る行と同じ形を出す。
28. **遅かった時の「状況」も残す** — 件数・キー名を一緒に記録する。
    数字だけでは直す手がかりにならない。
29. **ビルド時の見張り** — `scripts/check-size.mjs`。`npm run build` は警告だけ、
    `npm run size` は上限超過で失敗する。
30. **速さの回帰テスト** — `scripts/perf.mjs`（`npm run perf`）。**合否は出さない**。
    起動の通信量は `.nav` が出た時点で数え終える
    （その後まで数えると Service Worker が効き始めたかどうかで3倍ぶれる）。
