# 変革ノート（自己改革カレンダー）

夜勤（りらくる・終業は深夜0時前後）をしながら鍼灸国家試験（2027年）の勉強を続けるための、
自己改革スケジュール管理アプリ。海外の自己啓発コンテンツ「ゴーストモード」の7ステップを
ベースにした習慣トラッカー＋カレンダー。

公開URL: https://youtaix656-eng.github.io/-/henkaku-note/

React + TypeScript（Vite）・PWA・**保存は端末内のみ**。

## ゴーストモード 7ステップ（習慣の初期値）

| | 習慣 | 何をもって達成とするか |
|---|---|---|
| ① | 仲間 | 目標に向かう仲間と、今日ひとつでも接点を持てた |
| ② | 目標1つに集中 | 今日、最上位の目標に直接つながる行動を取れた |
| ③ | 無駄の排除 | 学習の時間帯に、娯楽・SNSを持ち込まなかった |
| ④ | ゼロ・モーニングルーティン | 起きてから15〜20分以内に、学習または作業を始められた |
| ⑤ | **就寝ルール（シフト対応）** | その日の就寝目標時刻までに寝られた |
| ⑥ | 報酬 | 強い刺激ではない報酬で、自分をねぎらえた |
| ⑦ | 週次振り返り | 週の区切りに3項目を書けた（週次画面で書くと自動でチェックが入る） |

7つは**初期値**であって固定ではない。編集・追加・休止ができる（`src/lib/habits.ts`）。

### ⑤だけ原典から変えている理由

原典は「夜11時就寝」だが、りらくるの夜勤は終業が深夜0時前後で物理的に守れない。
守れない目標を並べると「達成できないのが常態」になり、チェック自体をやめてしまう。
そのため **終業時刻を基準に就寝目標を計算する** 方式に置き換えた（`src/lib/shift.ts`）。

```
勤務日 : 終業時刻 ＋ bedWithinMinutes（既定90分）   例) 終業 00:00 → 目標 翌01:30
休日   : 固定の目標時刻（既定 23:00）
未設定 : 目標を出さない（勤務か休みか分からないまま目標だけ並べない）
```

時刻は「その日の 0:00 からの分」で扱い、24時間を超えた分はそのまま持つ（`1530` = 翌01:30）。
こうすると日付をまたぐ判定を特別扱いせず、引き算だけで済む。

### 3分の2バッファ法との統合（週次振り返り）

河野ゆかり『「仕組み化」勉強法』の考え方（鍼灸アプリの `bufferSession.js` と同じ前提）を、
週次振り返りの2視点として取り込んでいる。

- **管理者視点** — 計画そのものを見る（詰め込みすぎていないか・配分は合っていたか）
- **実行者視点** — やってみた感触と、詰まった点

画面の並びは **管理者視点が先**。先に「感触」を聞くと、うまくいかなかった週に自己否定から
入ってしまうため。文言は一貫して「**悪いのは実行役ではなく、無理な計画を立てたマネージャー**」
という前提で書く。責める表現が混ざっていないことは `weekly.spec.ts` / `shift.spec.ts` が
機械チェックする（`サボ` `怠` `意志` `ダメ` 等を含まないこと）。

### 瞑想（取り込んだ内容の実装）

出典は **本人が動画からまとめた要約**（2026-08-21 受領）。一次資料には当たっていないため、
効果はすべて「そう報告されている」という書き方に統一し、断定しない（`meditation.spec.ts` が
`必ず` `確実に` `保証` `誰でも` を含まないことを機械チェックする）。

要約から、行動に落ちる4点だけを実装している。

1. **10分が最小単位**。効果を感じる入り口であって、脳が変わるほどの介入時間ではない
   → タイマーの既定は10分。しんどい日用に3分も置く。
2. **初心者が急に1時間やると、雑念との格闘で逆にストレスになる**
   → `recommendMinutes` は **1段階ずつしか上げない**（10→20→30→60、同じ長さを5回積んで次へ）。
   飛ばした長さを選ぶと `shouldWarnJump` が注意を出す。3分は「逃げ道」なので段階には含めない。
3. **効果は「量」より「継続の一貫性」に依存する**
   → 習慣の達成判定は長さではなく「1回でも記録した日」。集計も**実践した日数**が主役で、
   合計分数は補助。週次でも「瞑想◯日/7」を先に出し、週1〜3日なら
   「長さを伸ばすより、短くても置く日を増やす」と助言する。
4. **期間ごとに報告されている変化が違う**
   → `EFFECT_STAGES`（1回／数週間／1〜2ヶ月／8週間のMBSR研究／数ヶ月〜1年）を
   実践日数に紐づけて表示し、次の段階までの残り日数も出す。

タイマーは実時間（`Date.now` の締切）で計算するので、画面を閉じてもズレない。
終わりの合図は WebAudio でその場で作る（音源ファイルを持たないのでオフラインでも鳴る）。
1分に満たない中断は記録しない（座っていない時間を実績にしない）。

**禁欲（オナ禁）の扱い**：出典自身が「生理学的効果の主張は根拠が弱い／誇張されている」と
書いているため、**日数カウンターは作っていない**（数えて煽ると、その弱い主張を強めてしまう）。
実装したのは「衝動が出た瞬間に気づいて手放す」という練習のほうで、習慣プリセット
`preset-urge` として置き、※要確認の注意書きを画面にそのまま出している。

### 最高の体調（取り込んだ内容の実装）

出典は **解説動画を本人がまとめた要約**（2026-08-30 受領）。書籍・原論文は未確認なので、
効果はすべて「そう紹介されている」水準で書く。

本書の構造は「文明病 →（体の）炎症 → 6つの領域」。**枠組みは説明であって行動ではない**ので、
文明病と炎症は読み物（`FRAMING`）として持ち、記録の対象にはしない。記録するのは6領域の行動だけ。

| 領域 | 記録するもの | 既存機能との関係 |
|---|---|---|
| 🦠 腸内環境 | 発酵食品の**種類**・食物繊維 | — |
| 🌿 自然に触れる | 外での分数（目安10分）・室内の自然 | — |
| 🌙 睡眠 | ベッドは寝る場所／日中の太陽光／夜は暗く | 就寝ルールと同じカードにまとめる |
| 🤝 人間関係 | 接点の濃さ（氏名は持たない） | 記録すると**①仲間**にも自動でチェック |
| 🌌 ぼんやりとした不安 | 感じたか・対処（宇宙／大自然／アート／瞑想） | **瞑想を記録した日は対処済みとして数える** |
| 📋 仕事のルール化 | 3のルール | `threeRules.ts` が持つ |

#### 炎症スコアを作らない

本書は不調を「体の炎症」で説明するが、**体内の炎症は検査で測るもので、行動のチェックから
数値化できない**。点数を出すと「今日の炎症は72点」のような根拠のない数字を信じさせてしまう。
数えるのは **「炎症を下げるとされる行動を、何日置けたか」** だけ。`condition.spec.ts` が
`score` という名前の関数が無いこと・週の集計が合計点を返さないことを機械チェックする。

#### 睡眠は2層に分ける

- `shift.ts` … **いつ寝たか**（シフトから決まる就寝目標に対する実績）
- `sleepQuality.ts` … **どう眠れたか**（寝つき30分以内／中途覚醒1回まで／20分以内に再入眠／睡眠効率85%以上）

画面は同じカードにまとめるが、ロジックは混ぜない。**記録していない項目は「分からない」のままにして、
睡眠不足だと断定しない**（本書は「一つでも外れたら睡眠不足」とするが、アプリは足りない項目を挙げるだけ）。
睡眠時間は7〜9時間の範囲で見て、短くても長くても責める文言は出さない。

#### 3のルールは日・週・月で1つの仕組み

キーだけ変えて同じ表に持つ（`'2026-08-30'` / `'w:2026-08-24'` / `'m:2026-08'`）。
**3つ埋めることを条件にしない**（1つでも書けていれば「書いた」）。上の階層から降ろせる
（今週の3つ → 今日、先週の「来週集中すべきこと」 → 今週の3つ）。
これまでの「今日の宣言」（一文）は3のルールに置き換えた。**同じことを2か所に書かせない**ため。
既に書かれた宣言は読めるように残してある。

### 食事の時間と量（取り込んだ内容の実装）

出典は **『できる男は超小食』の解説動画を本人がまとめた要約**（2026-09-02 受領）。
書籍・原論文は未確認。**この題材だけは、他より慎重に作ってある**。理由は3つ。

#### 1. 裏の取れない主張が混ざっている

「断食で脳から毒を排泄する」「消化はフルマラソン相当のエネルギーを使う」
「肉は腸内で腐敗して発がん」「牛乳のカゼインに発がん性」「1日1食でも痩せすぎない」は、
争いがある、または誇張とされる主張。**アプリの側から効果として断定しない。**
出典にそう書いてあることは隠さず `UNVERIFIED_CLAIMS` に並べ、1件ずつ「裏が取れていない」
「争いのある主張」「個人差がある」を添える。医療の判断が要るものは医師・管理栄養士へ回す。

#### 2. やってはいけない人がいる

`PRECHECKS` 6項目（血糖に関わる持病／服薬／妊娠授乳／成長期／摂食障害の経験／低体重）。
1つでも該当すると、カードの上部に「先に医師に相談してください」を**出し続ける**。
機能自体は塞がない（本人が決めること）が、警告は消えない。

#### 3. 数えて煽ると害になりうる

**断食の連続日数・記録更新を数える仕組みを作らない**（`summarizeMeals` が `streak` を
返さないことをテストが機械チェックする）。「食べない日を伸ばすほど良い」方向に押すと、
食事のことばかり考える状態や、体重が減り続ける状態を後押ししてしまう。
数えるのは **「無理なく続けられているか」と「止めどき」** だけ。

- `STOP_SIGNS` 6項目（ふらつき／頭がぼんやり／気分が落ちる／食べ物のことばかり考える／
  体重が減り続ける／生活に支障）。2週間ぶんを見て、**合計3回、または「食べ物のことばかり考える」
  「体重が減り続ける」は1回でも**、「いったん普通に食べてください」＋段階を戻すボタンを出す。
- 段階（3食 → 朝を抜く → 1日1食）は **1つずつしか上がらない**。
  サインが出ている間は上げない。同じ段階を14日続けてから上げる。
  「週末だけ整える」は並列の選択肢（忙しい人向けに出典が挙げているもの）。

#### 出典の数字が読めなかった箇所

出典は「前の食事から◯時間以上空ける」としているが、**受け取った文字起こしでその数字が
欠けていた**。勝手に数字を作らず、アプリの初期値（12時間）として持ち、設定で変えられる形にした。
**勤務日だけ短くする設定**もある（夜勤で長時間空けると負担になりやすいため。`shift` と連動）。

#### 何を食べるかは腸内環境へ寄せる

和食・発酵食品の話は『最高の体調』の🦠腸内環境とそのまま重なるので、
**食べたものの記録はそちらに一本化**し、この機能は時間と量だけを持つ。

### モンクモード（取り込んだ内容の実装）

出典は **海外式モンクモードの解説動画を本人がまとめた要約**（2026-09-02 受領）。原典・研究は未確認。

ゴーストモード7ステップと近い家系なので、**重なる部分は既存の記録へ寄せ、この層は重なって
いないものだけを持つ**。

| 出典の項目 | このアプリでの扱い |
|---|---|
| 1日10分の瞑想 | `meditation.ts`（実装ずみ）。記録すると🕯心にもチェックが入る |
| 加工食品を取らない | `condition.ts` の🦠腸内環境（実装ずみ） |
| 友人と距離を置く | **実装しない**（下の食い違いを参照）。代わりに「一人で集中した時間」だけ記録 |
| SNSの制限 | ゴーストモード③「無駄の排除」に、具体的なやり方（午前中は電源オフ／夜PCだけ／アプリ削除）を足す形 |
| 水2L・電解質・歩数・筋トレ・読書 | `monkMode.ts` に新規（既存に無いもの） |

#### 出典どうしが食い違う点は、そのまま見せる

| | 言っていること |
|---|---|
| **モンクモード** | 友人と距離を置き、一人になる時間を取る |
| **最高の体調** | 孤独だった人に友達ができると最大15年寿命が延びる。影響は禁煙より大きい |

**アプリはどちらが正しいかを決めない。** `CONFLICTS` として両方の言い分を並べて出す。
実装するのは「人間関係を切る」ではなく **「一人で集中した時間の確保」** のほう
（出典が挙げる例も、ビル・ゲイツが年に一度こもる、という時間の取り方）。
さらに `isolationWarning` が、**一人の時間だけが増えて人との接点が無い日が続いた時**に
「これは目標のための一人の時間でしょうか、それとも孤立に近づいているでしょうか」と問いかける
（決めつけずに、本人が答えられる形にする）。

#### 特に強い注意を付けた主張

- **朝に塩3〜4g** … 日本の食事はもともと食塩が多め。血圧・腎臓に不安がある人には勧められない。
  **このアプリは塩の量を記録も推奨もしない。** `MONK_PRECHECKS`（血圧／腎臓／心臓）に該当すると
  カード上部に警告を出し続ける。
- **ウォーキングの降圧作用は薬より効果的** … **服薬をやめる・減らす判断は必ず医師と**。
- 卵1日3個が完全栄養食／専門書で5年以内に確実にトップ5%／読書で年収が上がる／66日で脳の配線が変わる
  … いずれも `MONK_UNVERIFIED` に注意付きで置く。

#### 66日は「累計」でよい

出典自身が「66日連続は難しいので累計でよい」と言っている。実践期間の日数に **66日（モンクモード）**
を足し、選ぶとその説明が出る。既存の `cycleProgress` は元から「期間内に実践した日数」を数えるので、
累計の考え方とそのまま合う。

#### 運動は削らない

出典が「モンクモード中は運動が事実上ただ一つのストレス発散」と言っているので、
`bodyReminder` は **運動が足りない時だけ**声をかける（足りていれば黙る）。
運動した時刻を記録すると、`goldenWindow` が「運動後3時間は集中しやすいとされる」時間帯を出す（※要確認）。

### 起きて最初のルーティン（取り込んだ内容の実装）

出典は **ハル・エルロッドの朝の6習慣の解説動画を本人がまとめた要約**（2026-09-02 受領）。書籍・原典は未確認。

#### 「朝」を前提にしない

出典自身が **「必ずしも朝にやる必要はない。起きて最初にやってほしい」** と言っている。
このアプリの利用者は夜勤（終業が深夜0時前後）なので、「朝◯時に起きる」を前提にすると
そもそも実行できない機能になる。名前も判定も **「起きて最初の◯分」** で通し、
時計ではなく **起きてから何分で始めたか** を見る（ゴーストモード④と同じ20分以内の目安）。

#### 6ステップと、走らせる仕組み

瞑想 → アファメーション → イメージング → エクササイズ → 読書 → ジャーナル。
**順に走らせるランナー**として実装した（カードを並べるだけでは、順番にやる意味が消える）。
長さは3通り：**60分版**（出典の配分 5/5/5/20/20/5）・**6分版**（各1分）・**自分で決める**
（0分にしたステップは実行から外れる／順番も変えられる。出典も解説者も入れ替えている）。

#### 終えたステップは既存の記録へ書き込む

同じことを2か所に記録させないため、ランナーが終わると自動で入る。

| ステップ | 書き込み先 |
|---|---|
| 瞑想 | `meditation.ts`（addMeditation） |
| エクササイズ | `monkMode.ts` の運動（分と時刻。運動後の集中時間も出る） |
| 読書 | `monkMode.ts` の読書 |
| ジャーナル | `threeRules.ts` の**今日の3つ**（ランナーの中で直接入力できる） |

アファメーションとイメージングは、このアプリに対応する記録が無いので書き込み先を持たない。

#### アファメーションは数字と期限を見る

出典が「明確な数字や期限を必ず入れる」と言っているので、`checkAffirmation` が
数字・期限の有無を見て足りない点を伝える。**書けていなくても止めない**（直すのは本人）。

#### 寝る前の言い換え

出典：「朝起きて最初に考えることは、たいてい寝る前に最後に考えたことと同じ」。
就寝目標（`shift.ts`）と起床の目標時刻がそろっている日だけ、就寝ルールのカードに
**「今夜は◯時間も眠れます」** と出す。`sleepPhrase` は **「しか」を含む文を返さない**
（テストが機械チェックする）。出典の実験は著者1人が自分で試したもので研究ではない旨も添える。

#### 断定していないもの

数週間で人生が変わる／早起きしている成功者が多い（＝早起きが原因とは限らない）／
数字を入れるほど実現の確率が跳ね上がる／海馬の灰白質／記録するだけで痩せる／
寝る前の思い込みの実験（n=1）／**朝食を抜くと集中力が上がる**（これだけは強い注意付きで、
🍚食事の時間と量の「始める前の確認」へ回す）。

### 連続日数を煽らない

ゴーストモードは「最低1ヶ月」で、無期限の実践は想定されていない（燃え尽き防止のための区切り）。
連続日数を主役にすると1日抜けただけで台無しに感じるため、

- 主役は **「期間の◯日目 / 全◯日」** と **通算の実践日数**（途切れても消えない）
- 連続日数は3日以上のときだけ小さく出す（設定で大きく出すことも選べる／既定オフ）
- 期間の終わりに **続けるか・休むか・終えるか** を本人が決める画面を出す

### データを直す時

- **達成率の分母は「その日に有効だった習慣」**。あとから習慣を足しても過去の達成率は下がらない。
- 習慣は削除より **休止**（`archivedAt`）を既定にする。削除すると過去の記録が読めなくなる。
- 就寝目標は保存しない。設定を変えたら過去の日も新しい設定で読み直される。
- 習慣名は目次ルールと同じ扱い（**重複禁止・漢字を含むなら読み必須**）。

## 開発

```bash
npm install
npm run dev      # 開発サーバ
npm test         # ロジックのテスト（tsc → node --test、167件）
npm run build    # dist/ へビルド（Pages のサブパス配信のため base: './'）
npm run gen-icons # PWA アイコンの再生成（外部ライブラリ不使用）
```

テストは **`tests/*.spec.ts`**。CI が Node 20（TypeScript を実行時に読めない）なので、
`tsconfig.test.json` で一度 `.test-build/` へ出してから `node --test` で走らせる。
ファイル名を `*.spec.ts`／ディレクトリを `tests/` にしているのは、
**リポジトリ直下の `npm test`（`node --test` の再帰探索）に拾われないようにするため**
（拾われると、ビルド前の状態で実行されて落ちる）。このアプリのテストは
`.github/workflows/deploy.yml` の「Test (変革ノート)」で実行される。
