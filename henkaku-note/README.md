# 変革ノート（自己改革カレンダー）

夜勤（りらくる・終業は深夜0時前後）をしながら鍼灸国家試験（2027年）の勉強を続けるための、
自己改革スケジュール管理アプリ。海外の自己啓発コンテンツ「ゴーストモード」の7ステップを
ベースにした習慣トラッカー＋カレンダー。

公開URL: https://youtaix656-eng.github.io/-/henkaku-note/

React + TypeScript（Vite）・PWA・**保存は端末内のみ**。

## ゴーストモード 7ステップ（習慣の初期値）

| | 習慣 | 何をもって達成とするか |
|---|---|---|
| ① | 仲間 | 目標に向かう仲間と、今日ひとつでも接点を持てた |
| ② | 目標1つに集中 | 今日、最上位の目標に直接つながる行動を取れた |
| ③ | 無駄の排除 | 学習の時間帯に、娯楽・SNSを持ち込まなかった |
| ④ | ゼロ・モーニングルーティン | 起きてから15〜20分以内に、学習または作業を始められた |
| ⑤ | **就寝ルール（シフト対応）** | その日の就寝目標時刻までに寝られた |
| ⑥ | 報酬 | 強い刺激ではない報酬で、自分をねぎらえた |
| ⑦ | 週次振り返り | 週の区切りに3項目を書けた（週次画面で書くと自動でチェックが入る） |

7つは**初期値**であって固定ではない。編集・追加・休止ができる（`src/lib/habits.ts`）。

### ⑤だけ原典から変えている理由

原典は「夜11時就寝」だが、りらくるの夜勤は終業が深夜0時前後で物理的に守れない。
守れない目標を並べると「達成できないのが常態」になり、チェック自体をやめてしまう。
そのため **終業時刻を基準に就寝目標を計算する** 方式に置き換えた（`src/lib/shift.ts`）。

```
勤務日 : 終業時刻 ＋ bedWithinMinutes（既定90分）   例) 終業 00:00 → 目標 翌01:30
休日   : 固定の目標時刻（既定 23:00）
未設定 : 目標を出さない（勤務か休みか分からないまま目標だけ並べない）
```

時刻は「その日の 0:00 からの分」で扱い、24時間を超えた分はそのまま持つ（`1530` = 翌01:30）。
こうすると日付をまたぐ判定を特別扱いせず、引き算だけで済む。

### 3分の2バッファ法との統合（週次振り返り）

河野ゆかり『「仕組み化」勉強法』の考え方（鍼灸アプリの `bufferSession.js` と同じ前提）を、
週次振り返りの2視点として取り込んでいる。

- **管理者視点** — 計画そのものを見る（詰め込みすぎていないか・配分は合っていたか）
- **実行者視点** — やってみた感触と、詰まった点

画面の並びは **管理者視点が先**。先に「感触」を聞くと、うまくいかなかった週に自己否定から
入ってしまうため。文言は一貫して「**悪いのは実行役ではなく、無理な計画を立てたマネージャー**」
という前提で書く。責める表現が混ざっていないことは `weekly.spec.ts` / `shift.spec.ts` が
機械チェックする（`サボ` `怠` `意志` `ダメ` 等を含まないこと）。

### 瞑想（取り込んだ内容の実装）

出典は **本人が動画からまとめた要約**（2026-08-21 受領）。一次資料には当たっていないため、
効果はすべて「そう報告されている」という書き方に統一し、断定しない（`meditation.spec.ts` が
`必ず` `確実に` `保証` `誰でも` を含まないことを機械チェックする）。

要約から、行動に落ちる4点だけを実装している。

1. **10分が最小単位**。効果を感じる入り口であって、脳が変わるほどの介入時間ではない
   → タイマーの既定は10分。しんどい日用に3分も置く。
2. **初心者が急に1時間やると、雑念との格闘で逆にストレスになる**
   → `recommendMinutes` は **1段階ずつしか上げない**（10→20→30→60、同じ長さを5回積んで次へ）。
   飛ばした長さを選ぶと `shouldWarnJump` が注意を出す。3分は「逃げ道」なので段階には含めない。
3. **効果は「量」より「継続の一貫性」に依存する**
   → 習慣の達成判定は長さではなく「1回でも記録した日」。集計も**実践した日数**が主役で、
   合計分数は補助。週次でも「瞑想◯日/7」を先に出し、週1〜3日なら
   「長さを伸ばすより、短くても置く日を増やす」と助言する。
4. **期間ごとに報告されている変化が違う**
   → `EFFECT_STAGES`（1回／数週間／1〜2ヶ月／8週間のMBSR研究／数ヶ月〜1年）を
   実践日数に紐づけて表示し、次の段階までの残り日数も出す。

タイマーは実時間（`Date.now` の締切）で計算するので、画面を閉じてもズレない。
終わりの合図は WebAudio でその場で作る（音源ファイルを持たないのでオフラインでも鳴る）。
1分に満たない中断は記録しない（座っていない時間を実績にしない）。

**禁欲（オナ禁）の扱い**：出典自身が「生理学的効果の主張は根拠が弱い／誇張されている」と
書いているため、**日数カウンターは作っていない**（数えて煽ると、その弱い主張を強めてしまう）。
実装したのは「衝動が出た瞬間に気づいて手放す」という練習のほうで、習慣プリセット
`preset-urge` として置き、※要確認の注意書きを画面にそのまま出している。

### 連続日数を煽らない

ゴーストモードは「最低1ヶ月」で、無期限の実践は想定されていない（燃え尽き防止のための区切り）。
連続日数を主役にすると1日抜けただけで台無しに感じるため、

- 主役は **「期間の◯日目 / 全◯日」** と **通算の実践日数**（途切れても消えない）
- 連続日数は3日以上のときだけ小さく出す（設定で大きく出すことも選べる／既定オフ）
- 期間の終わりに **続けるか・休むか・終えるか** を本人が決める画面を出す

### データを直す時

- **達成率の分母は「その日に有効だった習慣」**。あとから習慣を足しても過去の達成率は下がらない。
- 習慣は削除より **休止**（`archivedAt`）を既定にする。削除すると過去の記録が読めなくなる。
- 就寝目標は保存しない。設定を変えたら過去の日も新しい設定で読み直される。
- 習慣名は目次ルールと同じ扱い（**重複禁止・漢字を含むなら読み必須**）。

## 開発

```bash
npm install
npm run dev      # 開発サーバ
npm test         # ロジックのテスト（tsc → node --test、79件）
npm run build    # dist/ へビルド（Pages のサブパス配信のため base: './'）
npm run gen-icons # PWA アイコンの再生成（外部ライブラリ不使用）
```

テストは **`tests/*.spec.ts`**。CI が Node 20（TypeScript を実行時に読めない）なので、
`tsconfig.test.json` で一度 `.test-build/` へ出してから `node --test` で走らせる。
ファイル名を `*.spec.ts`／ディレクトリを `tests/` にしているのは、
**リポジトリ直下の `npm test`（`node --test` の再帰探索）に拾われないようにするため**
（拾われると、ビルド前の状態で実行されて落ちる）。このアプリのテストは
`.github/workflows/deploy.yml` の「Test (変革ノート)」で実行される。
