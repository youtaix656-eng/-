# 資格ラボ（Shikaku Lab）

過去問をAIで教材に変えるための道具。
資格試験ごとの**対策法・勉強法・認知特性**から学習計画書を作り、
その計画書から**「自分専用の対策アプリ」を Claude Code に作らせるための設計書**まで出します。

公開先：https://youtaix656-eng.github.io/-/shikaku-lab/

- Vite + React（JSX。TypeScript なし・外部ランタイム依存なし）
- データは**端末の中だけ**（localStorage）。`src/lib/storage.js` はネットワークに触れません
- 画面のいちばん上に**ポモドーロタイマーを常設**

---

## 何ができるか

| | やること | どこ |
|---|---|---|
| ① | 受ける試験を選ぶ（19件同梱・自分で足せる） | `試験` |
| ② | 試験日と確保できる時間から逆算する | `計画 ①期間` |
| ③ | 認知特性に答える（**診断ではありません**・飛ばせます） | `計画 ②認知特性` |
| ④ | 試験の性格 × 認知特性から勉強法の提案を受け、自分で選ぶ | `計画 ③勉強法` |
| ⑤ | 学習計画書（Markdown）を出す | `計画 ④計画書` |
| ⑥ | 過去問をAIで教材に変えるプロンプトを作り、返答を取り込む | `変換` |
| ⑦ | 計画書から、自分専用アプリの設計書を出す | `設計` |

## 開発

```sh
npm install
npm run dev      # 開発サーバー
npm run build    # ビルド
npm test         # node --test test/*.test.mjs（114件）
```

## 直す時に守ること

このアプリが持っている「決めていること」は、ほとんどが**過去に実際に踏んだ失敗**から来ています。
消す前に、なぜそう書いてあるかを各ファイルの先頭コメントで確かめてください。

### 1. 手元に無い基準を持たない
- **毎年変わる数字（合格率・合格点・試験日・受験料）を `data/exams.js` に持たない。**
  持った瞬間に「アプリに書いてあったから」と古い数字を信じてしまう。
  代わりに `checkPoints`（公式サイトで自分で確かめること）を持つ。
  `test/exams.test.mjs` が正規表現で機械チェックする。
- **「合格に必要な時間」を出さない**（`lib/schedule.js`）。出せるのは「確保できる時間」だけ。
- **合否の予測を出さない**（生成する設計書にも「作らないもの」として書いてある）。

### 2. 認知特性は診断ではない
`lib/cognitive.js` が守っていること。
- **同点なら決めない**（`TIE_MARGIN`）。無理に1つに寄せると、他の入り口を試さなくなる。
- **回答が足りなければ断定しない**（`MIN_ANSWERED_RATIO`）。
- **未回答を0点として数えない**（「答えていない＝合わない」にしてしまう）。
- **「あなたは◯◯型です」と言わない。** 言い方は `profileLine()` の1か所に集約してある
  （画面ごとにブレないため）。テストが断定表現を機械チェックする。

### 3. AIをアプリから呼ばない
`lib/convert.js` の頭に理由を書いてある。出すのは「AIに貼るプロンプト」と「受け取る口」だけ。
プロンプトに必ず入れる決まり（`FIXED_PROMPT_RULES`）は**足せるが外せない**。とくに：
- **検索できない時に出典（URL）を書かせない**（「未確認（要出典）」と印を付けさせる）。
  もっともらしいURLを作らせるのが、この手のプロンプトで一番危ない事故。
- **毎年変わる数値・法改正には「※要確認」を付けさせる。**

### 4. 同じことを2か所に書かない
- 計画書の本文は `lib/plan.js` の `planMarkdown()` **だけ**が作る（画面もこの出力を見せる）。
- 設計書（`lib/spec.js`）は**計画書から導く**。計画を直せば設計書も変わる。
- 設計書に載せる画面は `SCREEN_RULES` ＋ `screensFor()` の**1か所だけ**で決まる。
  **選んでいない勉強法の画面を設計書に書かない**——全部入りを渡すと Claude Code は
  全部作ろうとして、どれも中途半端になる。
- **問題データは設計書に貼らない**（`questions.json` として別に渡す）。読ませる量が跳ね上がる。

### 5. ポモドーロ（`lib/pomodoro.js`）
- **残り時間は「終わる時刻」から毎回引き算する。** 1秒ずつ減らすと、タブを裏に回した時に必ずズレる。
- **連続日数を出さない**（`streak` を実装しないことをテストが機械チェックする）。
  途切れたことを気にして開かなくなるほうが、失うものが大きい。
- 音は端末の中で作る（音声ファイルを持たない）。休憩は飛ばせる（決めた形に人を合わせない）。

### 6. 目次・索引の共通ルール（全アプリ共通）
`data/toc.js` は各データから**自動生成**する（書き写さない）。`lib/yomi.js` が読み・並びを担当。
- 並びは **あ〜ん → A〜Z → その他**。
- **数字は読み方で振り分ける**（「4類危険物」→ よんるい… → や行）。
- **漢字の読みは絶対に推定しない。** 読みが無ければ「その他」に出して、入れ忘れを見えるようにする。
- タイトルは重複させない。
これらは `test/toc.test.mjs` がすべて機械チェックする。
`data/exams.js` に性格・出題形式の語彙を足したら、`TRAIT_READINGS` / `FORMAT_READINGS` にも読みを足すこと。

### 7. 行き止まりを作らない
- **押しても何も起きないボタンを出さない**（走っていない時に「一時停止」を出さない）。
- 取り込みで形が合わないものがあっても、**通った問題は取り込み、落とした理由を必ず出す**（黙って捨てない）。
- 期間が足りない時に「間に合いません」とだけ言わず、**削る候補**を出す（決めるのは人）。
- 認知特性も勉強法も**関門にしない**（答えなくても計画書と設計書は作れる）。

### 8. 日付
- `new Date('YYYY-MM-DD')` で読まない・`toISOString()` で書かない（UTCに直って前日になる）。
  `lib/schedule.js` の `parseDate` / `formatDate`、`lib/pomodoro.js` の `dayKey` を使う。

## ファイルの役割

```
src/
  lib/
    storage.js    端末内保存だけ。**ネットワークに触れない**（不変条件）
    useStore.js   小さな自作ストア（useSyncExternalStore）
    yomi.js       読み・並び・五十音の振り分け（目次の共通ルール）
    pomodoro.js   タイマーの計算（純関数のみ）
    cognitive.js  認知特性の集計。**診断をしない**ための決まりが入っている
    schedule.js   試験日からの逆算・フェーズ分け
    convert.js    過去問→AI変換（プロンプト生成・取り込み・重複判定）
    plan.js       学習計画書の組み立て（Markdown）
    spec.js       Claude Code 用アプリ設計書の組み立て
    myExam.js     自分の試験を足す（同梱と同じ形で扱う）
    steps.js      「次にやること」を状態から導く（手で印を付けさせない）
  data/
    exams.js               資格試験カタログ（19件）。**毎年変わる数字を持たない**
    methods.js             勉強法カタログ。効果の区分には必ず出典を付ける
    cognitiveQuestions.js  認知特性の質問（自己申告・診断ではない）
    toc.js                 目次（各データから自動生成）
```
