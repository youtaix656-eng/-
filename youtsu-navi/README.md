# 腰痛ナビ

セラピスト・整体師・有資格者が、施術中にお客様の状態を入力すると、
**安全トリアージ（レッドフラグ）** と **腰痛の推定原因パターン・施術方針・ホームケア** を
提示する判断支援アプリです。

公開URL: https://youtaix656-eng.github.io/-/youtsu-navi/

> 本アプリは医療機器ではなく、診断を行うものではありません。
> 表示される「推定パターン」「％」は診断名・診断確率ではなく、入力内容からの目安です。
> 最終的な施術判断は施術者本人が行うものとします。

## 現在のフェーズ（Phase 1 = 腰痛特化MVP）

企画書の「改善策 #8（初回リリースはスコープを絞る）」に従い、実装範囲を2機能に絞っています。

| 状態 | 機能 |
|---|---|
| ✅ | ① 症状入力 → 最適解提示（推定原因パターン・確率の目安・施術アプローチ・ホームケア） |
| ✅ | ② 安全トリアージ（レッドフラグ検知 → 施術中止／受診推奨アラート） |
| ✅ | 同意画面と同意履歴（改善策 #7）／資格別の業務範囲の出し分け（#4）／要配慮対象チェックリスト（#10）／根拠・出典管理（#1・#2）／ローカル保存のみ（#5）／汎用症状スキーマ（#6） |
| ⏳ Phase 2 | カルテ・履歴管理、音声メモ入力 |
| ⏳ Phase 3 | 知識ベース構築（YouTube・書籍の取り込み、二段階チェック #3） |
| ⏳ Phase 4 | 肩こり・膝痛など隣接症状への拡張 |

## 使い方

1. 初回起動時に同意画面と資格選択（あん摩マッサージ指圧師／はり師・きゅう師／柔道整復師／整体師・セラピスト）。
2. ホーム →「新しく評価する」で8ステップの入力（安全確認 → 部位 → 性質 → 発症と経過 → 動作 → 神経症状 → 生活 → ペインスケール）。
3. 結果画面に、上から **安全トリアージ → 要配慮対象チェックリスト → 推定パターン（％の目安・根拠・施術方針・ホームケア）** の順に表示。

安全確認のステップで緊急のレッドフラグを選ぶと、入力途中でもその場でアラートが出ます。

## 設計の要点

| ファイル | 役割 |
|---|---|
| `src/data/schema.js` | **汎用症状スキーマ**（改善策 #6）。タグ語彙（`aggr:flexion` 等）と自己検査 `validateSymptom`。他症状を足しても作り直しにならない土台 |
| `src/data/lowBack.js` | 腰痛モジュール（入力項目・ステップ定義）。他症状は同じ形で別ファイルを作り `symptoms.js` に登録する |
| `src/data/patterns.js` | 推定パターン11種（`evidence` / `against` / `requireTags` / 施術方針 / ホームケア） |
| `src/data/redFlags.js` | レッドフラグ定義（企画書 第6部の表そのまま＋感染リスク） |
| `src/data/precautions.js` | 妊産婦・高齢者などの禁忌／推奨／中止サイン（改善策 #10） |
| `src/data/licenses.js` | 資格別の業務範囲と手段（modality）（改善策 #4） |
| `src/data/sources.js` | 根拠となるガイドライン・法令の一覧と**監修ステータス**（改善策 #1・#2、Phase 1.5 で `reviewed` に更新） |
| `src/lib/triage.js` | タグ → トリアージ判定（`stop` / `refer` / `caution` / `clear`） |
| `src/lib/inference.js` | タグ → パターン採点 → 相対％（**根拠が1つも当たらない候補は出さない**） |
| `src/lib/scope.js` | 資格 × modality で業務範囲外の提案に警告を出し分ける |
| `src/lib/consent.js` | 同意文・同意記録（文言を変えたら `CONSENT_VERSION` を上げる＝再同意を求める） |
| `src/lib/storage.js` | **端末内保存のみ**（改善策 #5）。このファイルがネットワークに触れないことを不変条件とする |

### ロジックを直す時

- 判定は**すべてタグ経由**。入力UIを変えても `patterns.js` / `redFlags.js` は書き換え不要。
- 新しいタグを使う時は `schema.js` の `TAG_VOCABULARY` に追加する（未登録タグはテストが落ちる）。
- 医療内容を足す時は、必ず `sourceIds` で出典を紐づける（根拠のない提案を出さない方針）。
- 毎年変わる数字・解釈が分かれる事項には「※要確認」を付ける。

## 開発

```bash
npm install
npm run dev      # 開発サーバ
npm test         # ロジックのテスト（node --test）
npm run build    # dist/ へビルド（GitHub Pages のサブパス配信のため base: './'）
```

リポジトリ直下の `npm test` からも同じテストが実行されます（`node --test` の再帰探索）。
デプロイは `main` への push で `.github/workflows/deploy.yml` が
`/youtsu-navi` サブパスへ配置します。

## 未確定・要検討事項（※要確認）

- 各資格（あん摩マッサージ指圧師／柔道整復師／鍼灸師／整体師）の法的業務範囲の詳細
- 妊娠中の禁忌ツボ・強刺激の範囲（資格・流派による違い）
- 医師・専門家監修の依頼先・タイミング（Phase 1.5）
- クラウド同期オプション実装時のセキュリティ設計
- 個人情報保護法・薬機法との関係整理
