# ライフハック検索

困った時の言葉（「ねむれない」「片づけ」「先延ばし」）から、暮らしと仕事の工夫を引くための
小さな辞典です。**ブラウザだけで動き、入力も記録も端末の外へ出しません**。

公開先：https://youtaix656-eng.github.io/-/lifehack-search

## できること

| 画面 | 中身 |
|---|---|
| 🔍 さがす | キーワード検索（言い換え・カタカナ/ひらがな/全角半角の違いを吸収）。空白区切りは「かつ」、`-語` で除外。カテゴリ・手軽さで絞り込み。0件のときは「どの語を外すと何件見つかるか」を出す |
| 📑 目次 | 読み（ひらがな）順の あ〜ん / A〜Z 索引。五十音バーで飛べる |
| ★ 気になる | ★を付けた項目と、「試した／続けている／合わなかった」の記録・自分用メモ |
| ℹ️ このアプリ | 方針・根拠の種類の内訳・言い方の見張り・保存量の確認と消去 |

## 検索の考え方（`src/lib/search.js` が単一の正）

検索がいちばん失敗するのは、**困っている時に出てくる言葉と、データに書いてある言葉が違う**時です。
そこで次の形にしています。

1. **言い換え辞書を必ず通す**（`src/data/schema.js` の `SYNONYMS`）。「ねむれない」で「睡眠」の項目が出る。
   言い換えで当たった時は、カードにその旨を出す（本人が書いた語より弱く点を付ける）。
2. **正規化は文字数を変えない**（全角→半角・大文字→小文字・カタカナ→ひらがなだけ）。
   文字を削ると、当たった場所を元の文章に戻せなくなり、色付けがずれる。
3. **空白区切りは「かつ」**。1語も当たらないものは出さない（「たぶん近い」を混ぜると、なぜ出たのか分からなくなる）。
4. **0件で行き止まりにしない**。「この語を外すと◯件」を出す。勝手に検索し直さない（決めるのは人）。
5. 点数は「当たった場所の重み × 語の長さ」。固定点だと、短い語がたまたま当たっただけのものが、
   題名にそのまま入っているものに勝ってしまう。

## 中身を足す時の約束（`src/data/schema.js`）

- 要点は**自分の言葉**で書く。本や記事の文をそのまま写さない。
- **効きめを断定しない**（「必ず」「誰でも」「◯%改善」は書かない）。`src/lib/guard.js` が機械チェックする。
- **どこまで確かかを `basis` で必ず添える** — 名前のついた手法 / 書籍 / 昔から言われているやり方 /
  研究があるとされるもの（この種類だけは「※要確認」と書く）。**もっともらしい URL や研究の数字を作らない**。
- **からだ・不調（`category:'body'`）は `caution` 必須**。いつもと違う時は受診をすすめる側へ寄せる。
- **けがのおそれがある工夫（`risk: true`）は、やり方だけ書かない** — `prep`（始める前に確かめること）・
  `donts`（やってはいけないこと）・`caution` の3つを必ず持つ。donts は「危険です」で終わらせず、
  **何が起きるか**まで書く（割れて手を切る／急な温度差で割れる／空回りして手をぶつける）。
  **やめて切り替える先も必ず書く**——けがは「あと一回」で起きるので、「開くまで続ける」形にしない。
  危ない工夫を並べる時は、降りるための項目を1つ置く（例：「開けるのをやめる線を先に決める」）。
- **お湯・加熱を使う工夫は温度（℃）と上限まで書く**（ユーザー指定）。「熱めのお湯」は人によって
  40℃にも80℃にもなり、熱い側に寄せた時にやけどやガラスの割れが起きる。温度計が無い時の
  見分け方も添える。`test/data.test.mjs` が「お湯と書いてあるのに℃が無い」項目を落とす。
- **読み（`reading`）はひらがなで必ず書く**。漢字の読みは推定しない（無ければ目次の「その他」に落ちて、
  入れ忘れが見える形にしてある）。
- タイトルは重複させない。`related` は実在する id を指す。

これらはすべて `test/data.test.mjs`・`test/toc.test.mjs` が機械チェックします。

## 保存

`src/lib/storage.js`（localStorage）だけ。**このファイルはネットワークに触れません**（不変条件）。
残るのは「気になる」「やってみた記録・メモ」「検索の履歴（最大20件）」だけです。

## 開発

```bash
npm install
npm run dev      # 開発サーバー
npm test         # ロジックのテスト（node --test）
npm run build    # dist/ へ出力（GitHub Pages のサブパス配信のため base: './'）
```

`main` への push で `.github/workflows/deploy.yml` が `/lifehack-search` へ同梱してデプロイします。
