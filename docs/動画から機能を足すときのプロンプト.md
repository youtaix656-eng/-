# 動画の文字起こしから、機能・システム・AI社員を足すときのプロンプト

動画を1本読み込ませて、このリポジトリのアプリへ実装してもらうときに使う。
**下の「■ 貼り付ける本文」だけをコピーして、文字起こしと一緒に送る。**

6回ぶん（シン／AI仙人／ルパン／ラッキーマイナー月／ここな／加藤）の実装で
実際に効いたこと・実際に踏んだ失敗を、そのまま手順に落としてある。

---

## ■ 貼り付ける本文（ここから下をコピー）

```
【対象アプリ】
（ouro／鍼灸／腰痛ナビ／るるくる／変革ノート／睡眠トラッカー のどれか。迷ったら「判断して」）

【やってほしいこと】
下の文字起こしを読んで、対象アプリに 機能・システム・AI社員 を追加または修整してください。

【進め方（この順で。飛ばさない）】
1. まず動画の「芯」を3つ以内に絞って、1行で宣言してから始める。
   ・作り方の実演部分ではなく、**その人が失敗して学んだこと**を拾う。
   ・話者の商売（有料note・コンサル・特典・LINE登録）には引っ張られない。
2. 実装する前に、必ず既存を確認する。
   ・CLAUDE.md の機能一覧と、`grep -rln "<関連語>" src/lib src/components src/data`
   ・**「無い」と判断する前に必ず調べる。**（過去に既存機能を再実装しかけた）
   ・既にあるものは「既にある」と正直に言い、足すのは本当に無いものだけ。
3. 何を足すか／何を足さないかを先に伝える。既存・新規をはっきり分ける。
4. 実装する。CLAUDE.md の番号付きの決まりを1つも壊さない。
5. `npm run build` と `node --test`（対象アプリのテスト）を通す。
   新しい決まりを作ったら、**それを機械チェックするテストも書く**。
6. ローカルAI（`scratchpad/fakeai2.mjs`）＋ Chromium で、実際に画面を通しで動かす。
   コンソールエラー0件を確認する。近辺の既存フローも1つ以上あわせて再実行する。
7. ドキュメント（CLAUDE.md・README・ARCHITECTURE・PERFORMANCE）を更新し、
   コミット → `git push origin HEAD:main` → 公開先のファイルが手元と一致するまで確認。

【守ること】
・**手元に無い基準を持たない。** 業界平均・相場・「◯割なら健全」は書かない。
  比べるのは自分の数字の中の相対だけ。数字が無い所は「不明」と出す。
・**当てずっぽうを断定で書かない。** 当たった語がある時だけ根拠を見せる。
・**行き止まりを作らない。** 押しても何も起きないボタン・抜けられない関門を作らない。
・**通せない関門にしない。** チェックは数えるだけ。埋めなくても先へ進める。
・**勝手に進めない・勝手に削らない・勝手に昇格させない。** 提案するだけ。
  費用の出る実行は必ず人が押した時だけ。承認と日／月の上限は必ず通す。
・端末内保存のまま（サーバーを持たない・BYOK・`lib/storage.js` はネットワークに触れない）。
・外部ランタイム依存を増やさない。
・**AI社員を足すなら `data/employees.js` の `EXTRA_NAMES` も3名ずつ足す**
  （役職数×席数を下回ると別の役職に同じ名前が回る。`order` の重複にも注意）。
・**起動時に読む量を上げない。** 増えたら、同じだけどこかを軽くして相殺する
  （`npm run size`。目安を超えたら、上げずに下げる）。
・**同じ内容を2か所に持たない。** 結びつきは片方向だけ（`deal.taskIds` の失敗を繰り返さない）。

【出してほしいもの】
・動画の芯（3つ以内）と、それを何にしたか
・**既にあったもの／新しく足したもの**の切り分け
・実装中に見つけた既存のバグがあれば、それも直して報告
・**自分の前の説明が間違っていたら、隠さずその場で訂正する**
・公開URLと、配信中のファイルが手元と一致した確認

【文字起こし】
（ここに貼る）
```

## ■ 使い方のコツ

- **1本ずつ**送る。2本まとめると芯がぼやける。
- 対象アプリが決まっていなければ空欄でよい（内容から判断する）。
- 「30分あげます。何度も試行錯誤してください」と足すと、
  実際にアプリのロジックを走らせて数字を出し、作り直しまでやる。
- 「PDFに一覧としてまとめて」と足すと、A4のPDFにして渡す。
- 実装まで要らず、まず案だけ見たい時は【やってほしいこと】を
  「追加したほうがいいことを、既存と重複しない形で全部挙げてください（実装はまだしない）」に差し替える。

## ■ これまでに踏んだ失敗（同じことを繰り返さないための記録）

| 失敗 | いま防いでいる方法 |
|---|---|
| 既存機能を「無い」と誤認して再実装しかけた | 手順2の grep を必ず先に |
| 役職を3つ足したら名前が足りず、別の役職に同じ名前が回った | `EXTRA_NAMES` も3名ずつ |
| 役職の `order` が既存と重複した | 足したら必ずテストを回す |
| 起動時に読む量が目安を超えた | 増えたぶんを別の切り出しで相殺 |
| `parseSections(x).deliverable` が必ず undefined | `.sections.deliverable`。テストが見張る |
| 売上0・費用0なのに「AI費用のほうが多い」と嘘 | 動いていないものを赤字と書かない |
| 履歴があるのに「まだ1周も回していません」 | 件数と食い違う文を出さない |
| 相場・業界平均を書きそうになった | 手元に無い基準は持たない |
| 「6か月目に顧問だけで55万」が仮定依存だった | 感度を振り直し、その場で訂正した |
