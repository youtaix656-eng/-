# 体調カルテ（私の体調管理アプリ）

セラピスト／期間工として働く自分自身の体の不調（痛み・張り・違和感）を時系列で蓄積し、
試した対応策（ストレッチ・トレーニング・セルフケア）とその効果を記録するための **個人専用 PWA**。
**React + TypeScript / Vite / PWA・端末内保存のみ**（公開先：`/-/taicho-karte`）。

施術者向けの「腰痛ナビ」（客観的な施術知識のデータベース）とは役割が違い、こちらは**主観的な自己記録**に特化する。
1人用アプリで、マルチユーザーは持たない。

## いま入っているもの（Phase 1 = MVP）

| 画面 | 中身 |
|---|---|
| ホーム | 「症状を記録」「対応策を記録」の2つの大きなボタン／直近7日・30日のサマリー（件数・記録した日数・部位別の回数・VASの幅）／最近の症状・対応策 |
| 症状を記録 | 体の図（前面／背面の簡易 SVG）をタップして部位を選ぶ→左右（左／右／両側）→VAS 0〜10→発生タイミング（施術中／施術後／起床時／勤務中／その他＝自由記述）→専門用語メモ（例：Tinel様所見、硬結の有無）。記録日時は自動。保存すると、その症状に紐づけた状態で対応策の入力へ進める |
| 対応策を記録 | クイック選択（設定で編集できる）＋自由入力／実施日／効果の自己評価（悪化／変化なし／軽減／大幅改善）／どの症状に対する対応策か（直近30日の症状から複数選べる） |
| 症状の一覧・検索 | 部位・日付範囲・VAS下限・メモの文字で絞り込み。新しい順／古い順／強い順。開くとメモと、その症状に試した対応策がまとめて見える。編集・削除・その症状への対応策の追加 |
| 対応策の一覧 | 効果で絞り込み・内容の文字・日付範囲。**既定は「効果があった順」**（同じ効果なら新しい順）。編集・削除 |
| 設定 | クイック選択項目の追加・並べ替え・削除／JSON の書き出し・取り込み／すべて消す |

Phase 2 以降（週次・月次サマリーのグラフ、出勤前・退勤後のコンディション記録、機能連鎖マップ、効果ランキング、
受診目安リマインド、音声メモ、睡眠トラッカー連携、腰痛ナビ逆引き）は MVP の後に別途指示を受けてから足す。

## このアプリの決まり（ここが単一の正。変える時はこのファイルとテストを一緒に直す）

1. **保存するのは入力そのものだけ。** 部位別の件数・効果順の並び・VASの幅は `src/lib/summary.ts`／`filters.ts` が
   毎回 `symptoms`／`cares` から導く（ロジックを直しても過去の記録を読み直せる）。
2. **診断しない。** VAS は本人が付けた数字をそのまま出す。**平均を出さない**（1と9が1回ずつの平均5は
   「中くらいが2回」ではない。`tests/rules.spec.ts` が `average`／`mean` を返す関数の不在を機械チェック）。
   効果の4段階は並び替え用に `rank` を持つが、**画面には点数を出さない**（記号＋言葉で出す。テストが `.rank` の画面への露出を弾く）。
3. **左右は「本人から見た左右」で持つ**（`src/data/bodyRegions.ts`）。前面図では本人の左が画面の右に来るので、
   図の中にも「左」「右」の文字を出し、`tests/bodyRegions.spec.ts` が座標と side の対応を機械チェックする。
   左右のある部位をタップしたらタップした側を初期値にし、「両側」へは手で変える。
4. **部位は `src/data/bodyRegions.ts` が単一の正。** 1件足せば図・一覧の絞り込み・表示名が自動で追従する
   （読みは手で持つ。漢字の読みを機械で当てない）。
5. **`src/lib/` はネットワークに触れない**（`fetch`／`XMLHttpRequest`／`WebSocket`／`sendBeacon` を持たないことをテストが見張る）。
   将来のクラウド同期はこの層の外側に別モジュールとして作り、既定オフのオプションにする。
6. **外から来たもの（保存済みの古い形・取り込んだファイル）は必ず `normalizeState` を通す**（`src/lib/storage.ts`）。
   必須項目（id・日時・部位・VAS）が読めない記録は**黙って別の値に置き換えず捨てる**。存在しない症状への紐づけは外す。
   取り込みは「今のデータを置き換える」と分かる確認を必ず出す。
7. **症状を消しても、紐づいていた対応策は残す**（紐づけだけ外す）。対応策は症状が無くても記録できる。
8. **日付を UTC で扱わない**（`toISOString()`／`new Date('YYYY-MM-DD')` を使わない。`src/lib/date.ts` で組み立てる）。
9. **色だけに意味を持たせない。** VAS は必ず数字、効果は記号（▼／－／▲／▲▲）＋言葉を一緒に出す。
10. **画像ファイルを持たない**（アイコンは `scripts/gen-icons.mjs` がその場で焼く。体の図は SVG でその場に描く）。
11. **画面に出す文にマークダウンを書かない。**
12. **氏名・連絡先を持たない**（1人用なので欄自体が無い）。

## データモデル（`src/types/index.ts`）

- `SymptomRecord { id, at, regionId, side, vas, timing, timingOther, note }`
- `CareRecord { id, date, at, content, effect, symptomIds[] }`
- `Settings { quickCareItems[], lastView }`

## 開発

```sh
npm install
npm run dev       # 開発サーバー
npm test          # tsc で .test-build/ へ出してから node --test
npm run build     # tsc && vite build
npm run icons     # PWA アイコンを焼き直す
```

テストは `tests/*.spec.ts`（ルートの `npm test` の再帰探索には拾われない名前にしてある。kundalini／earpomo と同じ）。
